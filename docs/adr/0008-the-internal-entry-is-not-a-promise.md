# The Internal entry is published without a promise

0.6.0 cut the root entry of `@fluent.xyz/connect` to the names the package keeps (FLU-1622), and the helpers the widget is built from (the Default tokens, the balance reader, transfer validation and call building, the Network helpers, the families client) left it with the rest. A host that needs them (the Fluent Connect dashboard in `frontend-monorepo`) copied the modules into its own tree, where they drift from the SDK silently, and every other such host would write the same copies. Publishing `@fluent.xyz/connect-sdk` was rejected: it is bundled into `@fluent.xyz/connect`, and a second published package needs its own API cut, lock, version and release procedure. Re-exporting the helpers from the root entry was rejected: each name would become a promise kept after 0.6.0, and the widget's own `FluentTokenDefinition`, with `native` and `gasPriority`, collides with the root entry's. So the package carries a second entry, `@fluent.xyz/connect/internal` (`packages/connect/src/internal.ts`), the Internal entry: the helpers the widget uses, importable by name, with no promise about their names or shapes across releases.

## Consequences

The lock tests (`exports`, `closure`, `vendorMarkers`) hold the root entry alone, and the Internal entry has none: a name there may change or go in any release, a patch included, and `packages/connect/docs/internal.md` says so to the host, who reads that page at every upgrade. A name a host comes to rely on is promoted by moving it to the root entry, through the maintainer's edit of the lock (`docs/standards/public-api.md` A8), never by promising it where it is. The two entries are built as two bundles (`splitting: false` in `packages/connect/tsup.config.ts`), so a module both reach is built twice; nothing the Internal entry reaches keeps mutable module state, and no class crosses the two, so the copies cannot disagree. The root entry's `FluentTokenDefinition` (an Integrator token, ADR 0001) and the Internal entry's (a Default token, with `native` and `gasPriority`) share a name and differ on purpose; a host that uses both renames one at import.
